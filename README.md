# 同花顺模拟仓管家

通过 Android 手机上的同花顺模拟仓执行股票计划，支持自动挂单、持仓核对、止盈止损和到期退出。手机 App 用于查看状态、修改策略参数及手动检查补执行。全部交易入口限定为模拟仓。

支持手机本机独立运行，也支持电脑通过 USB 或服务器通过云手机 ADB 控制执行。手机本机完成部署后，执行器可以在关闭管理 App、拔掉 USB 后继续运行。

## 下载与升级

在 [GitHub Releases](https://github.com/Kai-mister/tonghuashun/releases/latest) 下载最新版本。

| 文件 | 用途 |
| --- | --- |
| `sim-manager.apk` | Android 管理 App |
| `ths-sim-upgrade.zip` | 已部署手机的升级包，包含 APK、后台代码、升级脚本和本说明 |

**升级本次功能需要同时更新 App 和手机后台。** 已部署过的手机可在安装了 Android SDK Platform Tools 的 macOS 或 Linux 电脑上执行以下步骤。

1. 解压 `ths-sim-upgrade.zip`。
2. 用 USB 连接唯一一台目标手机，解锁并授权 USB 调试。
3. 在解压目录执行以下命令，在手机上完成安装确认。

```sh
adb devices
sh scripts/upgrade-phone.sh
```

升级沿用原有配对、设置、暂停状态和策略账本。安装后打开「模拟仓管家」，确认能加载策略设置和运行状态。

全新手机需要先部署 Android arm64 Python 运行时、UI 自动化服务、后台程序、股票接口令牌，并完成 App 配对。目前升级包仅适用于已部署过的手机；APK 安装本身不包含完整执行环境。

## 在 App 中管理策略

App 显示模拟账号、策略状态、盘前持仓核对和最近策略委托。点击「暂停策略」会在当前一轮结束后暂停，已提交的委托继续有效。点击「启动 / 恢复策略」沿用同一账本继续执行。

### 金额与时间

在「策略设置」输入参数，点击「保存设置」。

| 设置 | 默认值 | 规则 |
| --- | --- | --- |
| 建议金额 | 10,000 元 | 按合法申报数量选择最接近该金额的数量 |
| 最低金额 | 5,000 元 | 委托金额下限 |
| 最高金额 | 20,000 元 | 委托金额上限 |
| 每天挂单时间 | 09:20 | 北京时间，格式为 HH:MM |

金额按委托限价计算，不含费用，须满足最低金额 ≤ 建议金额 ≤ 最高金额。两个数量同样接近建议金额时取较小值；没有符合范围的可申报数量则跳过。

挂单时间可设置为 09:15–11:29 或 13:00–14:59。程序在所选分钟读取当天计划并逐笔提交，手机操作耗时可能导致部分股票错过这一分钟。可通过「检查并补执行」处理遗漏。当前按周一至周五判断交易日，法定休市日历尚未接入。

### 激进与保守策略

| 策略 | 买入档位 |
| --- | --- |
| 激进 | 优先浅回调；接口没有浅回调时使用深回调 |
| 保守 | 使用深回调 |

买入限价取所选档位的 `buy_high`，止盈、止损也取自同一档位。保存设置后，尚未提交的买单使用新参数；已有买单及策略持仓继续使用原计划的价格和退出条件。

### 检查并补执行

点击按钮并确认后，执行器串行处理一次检查。策略暂停时也可以执行本次检查。

- 核对当日已有委托和成交。
- 在可挂单时段重新读取当天股票计划，补交尚无提交记录的买单。
- 在盘前核对或盘中时段检查策略持仓，盘中处理已触发止盈、止损或到期退出的卖单。
- 在 App 展示检查结果，以及未完成的操作。

回执不明的订单保留待核对状态，避免重复提交。已有提交记录的买单，包括人工撤销的买单，会保留原记录。该按钮不清除账本，也不会重新提交所有历史委托。周末、午休及收盘后不补单。

## 持仓监控和卖出

次日盘前从提交过买单的股票开始核对持仓，即使本地成交记录为 0，也会查询模拟仓。提交买单前保存总持仓基准；出现回报丢失时，使用持仓变化尝试恢复策略数量。有其他同代码交易导致归属不清时保留待核对状态。

盘中依据策略剩余持仓和实际可卖数量监控最新价。达到止盈点、跌至止损点，或到达 `planned_sell_date` 的 14:50 时触发退出。卖单使用模拟客户端卖出页显示的报价下限，持续核对部分成交与剩余股数。触发价与实际成交价可能不同，成交取决于盘口。

为保留项目调试仓，当前代码针对模拟账号显示值 `**1326` 的 `002222` 排除了 100 股。其他部署者需检查这一固定规则。行情来自同花顺手机页面，各股票依次读取，每轮结束后等待 3 秒；实际刷新间隔还包含页面操作耗时。

## 手机独立运行

手机本机部署目录为 `/data/local/tmp/ths-sim`。管理服务和 UI 自动化服务使用本机回环连接，管理 App 与执行器单独运行。

执行器在操作同花顺前检查屏幕状态，普通熄屏时会尝试唤醒，并请求系统解除无需凭据的锁屏。系统要求密码或指纹时需手动解锁。系统深度休眠或终止进程会影响准点执行。

手机需保持联网，并允许同花顺前台操作。手机重启后，先解锁，再通过已授权的设备 shell 启动服务。

```sh
sh /data/local/tmp/ths-sim/phone/background.sh
```

`state/` 保存设置、日志、暂停标记、管理配对凭据及 SQLite 策略账本。账本用于恢复状态和避免重复挂单，升级时应保留。

## 电脑 USB 调试

安装 Python 3.12 和 Android SDK Platform Tools，将 adb 加入 PATH。手机开启 USB 调试，连接数据线并授权。在仓库根目录执行以下命令。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py devices
.venv/bin/python run.py check
.venv/bin/python run.py serve
```

默认选择唯一的 USB 设备，多台设备可使用 `--serial 序列号`。REST 服务监听 `127.0.0.1:8000`，浏览器打开 `/docs` 查看参数。

| 功能 | HTTP 接口 |
| --- | --- |
| 打开同花顺 | POST /ths/open |
| 确认模拟仓 | POST /ths/set_mode?mode=simulate |
| 账户与持仓 | GET /ths/account、GET /ths/positions |
| 当日委托 | GET /ths/orders |
| 当日成交 | GET /ths/fills |
| 买入、卖出、撤单 | POST /ths/buy、POST /ths/sell、POST /ths/cancel |

检查响应中的 `success` 和 `error`，并用委托、成交记录确认最终结果。

## 云手机运行

云手机需支持 ADB 和 uiautomator2。按云厂商要求建立连接或隧道，在云手机中安装同花顺并登录模拟账户，然后在控制机执行以下命令。

```sh
# 替换为云平台提供的地址或隧道本地端口
.venv/bin/python run.py check --cloud 127.0.0.1:15555
.venv/bin/python run.py worker --cloud 127.0.0.1:15555
```

已通过厂商工具连接的设备也可使用 `--serial`。外部执行器的账本默认位于 `~/.local/state/ths-sim/strategy.sqlite3`，设置文件位于同目录的 `settings.json`。每个模拟账户使用一个执行进程及对应账本，避免多个控制端同时操作界面。

## 股票计划接口与凭据

后台读取 `stock_api.py` 中配置的 `https://192.255.236.236:8000/api/stocks`。每台执行设备需要配置服务端认可的 Bearer 令牌，保存为当前执行用户的 `~/.config/redis-racknerd/stock-api.token`。手机本机脚本会将执行用户目录设为部署目录。令牌不随 APK 分发。

```sh
.venv/bin/python stock_api.py
.venv/bin/python stock_api.py 002222
.venv/bin/python premarket.py
```

`premarket.py` 命令输出默认参数下的计划预览，App 保存的设置由后台执行器加载。接口包含股票代码、买卖计划日期，以及浅回调和深回调各自的买入区间、止盈点和止损点。

管理 App 每台设备单独配对。部署时在 `state/manager.key` 写入随机 32 字节的十六进制串，限制为 shell 用户可读，再通过 ADB shell 向 `cn.local.simmanager/.Pair` 发送名为 `key` 的字符串。接收器要求系统 DUMP 权限。重新安装并清除 App 数据后需重新配对。

## 开发与验证

```sh
.venv/bin/python -m unittest discover -s tests
```

Android APK 构建脚本为 `android/build.sh`，需要设置 JDK、Android SDK 和签名相关环境变量。推送 `v*` 标签后，GitHub Actions 将仓库中的签名 APK 和后台升级包发布到 Releases。

USB 下单、成交查询、撤单和普通熄屏唤醒已在 PJX110 模拟仓验证。新版金额、时间、策略设置及补执行已通过自动化测试和本地管理接口验证，真机升级验证待完成。
